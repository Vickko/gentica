# LLM驱动的TRPG系统：核心Ideas与方法论

## 项目愿景

构建一个基于DND/TRPG形式的泛化文字游戏系统，其中：
- LLM监督LLM扮演角色
- 玩家作为角色之一参与
- 支持多模态扩展（未来）

## 核心理论：单Agent vs 多Agent

### 上下文展开理论

**核心观点**：单Agent和多Agent的本质区别在于"上下文是否充分展开"

**关键发现**：
- LLM在直接输出时可能产生错误，但在新上下文中检查时能发现问题
- 例子：Code Agent通过反复challenge编译器来修正代码
  - 编译器提供客观反馈 → Agent修正 → 对用户呈现为"一次写对"
  - 将编译器替换为检查LLM，原理相同，只是效果略差

**系统设计的本质**：通过架构强制展开特定场景下的上下文

### 当局者迷，旁观者清

**重要发现**：有时拥有上下文反而不利于发现问题

- 专门用于检查的LLM可能比开启thinking的同一个LLM更有效
- 原因：检查者需要保持"中立视角"
- DND类比：不能让玩家自己判断行为是否合理，必须有独立的主持人

## 系统架构设计

### 主持人(Game Master)的核心职责

#### 1. 世界一致性维护（最重要！）

**定义**：确保所有角色感知到的世界状态保持一致

**具体示例**：
- 所有角色进入同一房间时，门的开/关状态必须一致
- 某角色踢倒椅子 → 所有后续进入者都能感知到这个变化
- 不能让各角色自行臆想环境状态

**实现机制**：
- 主持人维护世界状态（可能借助Memory Bank或RAG）
- 主持人拥有"上帝视角"
- 动态为各角色装载适当的上下文

#### 2. 多视角处理

**复杂性**：
- 客观事实 vs 主观感知
- 不同角色可能因观察力、立场、位置不同而感知不同
  - A看到完整场景
  - B听力好但视线受阻
  - C距离远，只能看到模糊的轮廓

**职责**：主持人需要为每个角色定制化其"可感知内容"

#### 3. 合理性判定

判断角色的行为/操作是否符合：
- 世界规则
- 角色能力
- 物理/逻辑常识

#### 4. 多方交互协调

处理复杂的多角色会话：
- 谁在对谁说话
- 其他人能听见什么
- 距离导致的信息衰减
- 神态、语气等非语言信息传递

## MVP方案

### 最小可行产品的边界

**核心组件**（baseline，缺一不可）：
- 1个主持人LLM
- 至少2个角色LLM
- 世界一致性维护机制

**去掉主持人 → 退化为LingChat**

### 推荐的MVP实现路径

1. **使用现成的世界观**
   - 例如：鸣潮的世界设定和人物关系
   - 优势：避免从零创作的困难

2. **创造小场景测试**
   - 已有剧情脉络
   - 让角色在受限场景中互动
   - 主持人专注于维护一致性

3. **角色扮演原则**
   - 主持人不直接扮演角色（或最小化）
   - 主要角色都由独立LLM扮演
   - 避免"主持人既当裁判又当运动员"

## 开发方法论

### 1. 先有范例，再建系统

**核心原则**："如果自己都不知道怎么做是好的，很难教会AI做好"

**具体步骤**：
1. 收集真实跑团数据作为参考
2. 找到最简化的理想跑团文本（1主持人 + 2角色）
3. 手动推演理想情况下的文本产出
4. 基于理想文本反推系统需求

### 2. 用例驱动开发

**挑战**：
- 用例和评估体系构造困难
- 需要既懂TRPG又懂LLM系统

**解决方案**：
- 从真实跑团记录中提取测试用例
- 关注"世界一致性"的边界情况
- 设计能量化的评估指标

### 3. 识别核心与次要

**陷阱**：容易先做不重要的功能

**方法**：
- 持续质询："这是baseline必需的吗？"
- 世界一致性 > 多视角处理 > 其他特性
- MVP要能"转起来"，即使功能简陋
